# Pixel HUD

Run **Tools > Zhuzbai > Apply Pixel HUD**, then **Tools > Zhuzbai > Validate Pixel HUD**.
The command migrates only the existing MainLevel HUD; it does not regenerate the level.
It saves MainLevel, including any unsaved scene edits. Run outside Play Mode and Prefab Mode.

The top-left HUD contains a red pixel heart with current/max HP and the original gold coin
sprite with collected/total coins. Both counters use original bitmap digit sprites, matched
dark translucent panels, subtle shadows, and a consistent 12-pixel gap. No external fonts,
downloads, TMP imports, or packages are needed for the counters.

The existing FoundationHud still listens to PlayerHealth.Changed and LevelSession.Changed.
The setup connects the new displays to that component, disables the previous Status object,
and preserves level completion via a separate centered banner. The controls hint remains
below the new counters. The old status reference remains for compatibility with unconverted
Phase 1 scenes.

The Canvas scales from 1280 x 720. A runtime wrapper applies Screen.safeArea and updates when
the screen/orientation changes. The counters remain horizontally anchored at the upper-left;
on narrow safe areas, the row scales together to fit. All decorative graphics have raycast
targets disabled so they will not block Assignment 7 mobile controls. This display-only HUD
does not require an EventSystem or input module.

## Apply and test

1. Wait for scripts to compile, open `Assets/Scenes/MainLevel.unity`, and run Apply Pixel HUD.
2. Run Validate Pixel HUD; Console should report success.
3. In a 16:9 Game view, press Play. Expect heart **3/3** and coin **00/08** with the default level.
4. Collect a coin with the existing player controls: expect **01/08** without any manual refresh.
5. Choose **Tools > Zhuzbai > Test Pixel HUD Damage (Play Mode)** to call the existing health
   system. Expect **2/3**; wait more than one second between tests because damage invulnerability
   is preserved. Further damage eventually respawns the player and restores **3/3**. This helper
   never saves gameplay state. Alternatively, use any existing damage source in your level.
6. Reach the exit gate: the completion banner should appear while the counters stay visible.
7. Change Game view between 16:9, a tall portrait resolution (for example 720 x 1280), and a
   wide mobile landscape resolution. Check that the counters stay horizontal and readable.
   If Device Simulator is installed, test a notched device and rotate it to check safe-area placement.
8. Stop Play Mode and apply again: there should still be exactly one safe-area wrapper,
   two counter panels, and one completion banner. Existing scene layout and player tuning remain.

Apply updates only its own UI subtree, the legacy Status visibility, the controls hint placement,
the existing Canvas display settings, and FoundationHud display references. It keeps health and
session references intact, reuses existing generated sprites, and never touches gameplay prefabs,
Input Actions, animation controllers, packages, or project settings. It opens MainLevel additively
if needed; for gameplay testing, keep only MainLevel loaded to avoid other scenes' cameras.

## Files

Source:

- `Assets/Scripts/Runtime/FoundationHud.cs` — existing event subscriptions, new display references.
- `Assets/Scripts/Runtime/PixelNumberDisplay.cs` — pixel glyph rendering.
- `Assets/Scripts/Runtime/PixelHudSafeArea.cs` — safe-area anchoring and narrow-screen fitting.
- `Assets/Scripts/Editor/PixelHudSetup.cs` — Apply, Validate, and Play Mode damage test commands.
- `Assets/UI/README.md` — this guide.

Generated by Apply, through Unity APIs:

- `Assets/UI/PixelHUD/Heart.png` — original red heart, Point filtering, no mipmaps.
- `Assets/UI/PixelHUD/Glyphs/0.png` through `9.png`, plus `Slash.png` — original 3 x 5 glyphs.
- Unity-generated `.meta` files for these assets and folders.

Apply saves the updated `Assets/Scenes/MainLevel.unity`. Existing
`Assets/Sprites/Foundation/Coin.png` is reused without editing it.

Source compilation can be checked independently; actual Canvas layout and gameplay verification
require running Apply and the Play Mode checks in Unity.
